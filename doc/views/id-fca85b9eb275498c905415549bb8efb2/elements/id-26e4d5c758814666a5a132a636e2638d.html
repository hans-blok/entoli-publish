ENTOLI AGENT SERVICES ()
Entoli Agent Services 1. Doel van de view De view Entoli Agent Services beschrijft hoe een Agent als dienst wordt gespecificeerd, welke capabilities via Agent Intents beschikbaar worden gesteld en hoe het gedrag daarvan wordt bestuurd door regimes, regels en canonieke semantiek. De view verbindt daarmee kennis, dienstverlening, gedragsbesturing, regels en packaging. 2. Kernstructuur Een Knowledge Specification (Kennisspecificatie) specificeert de kennis waarbinnen één of meer Agents (Functies) opereren. Een Agent stelt zijn capabilities beschikbaar via één of meer Agent Intents (Agent-intenties). Een Agent Intent representeert daarmee een afzonderlijk aanroepbare bedoeling of functie van de Agent. De primaire structuur is daarmee: Knowledge Specification → Agent → Agent Intent 3. Besturing Het gedrag van Agent en Agent Intent wordt langs verschillende onafhankelijke assen bestuurd. Reasoning Mode bestuurt het redeneren van de Agent. Source-regime bestuurt de omgang met bronnen, Synthesis-regime de wijze waarop betekenis mag worden behouden, gerelateerd of gegenereerd, en Task Mode de aard van de taakuitvoering van een Agent Intent. Source-regime, Synthesis-regime en Task Mode worden op hun beurt bestuurd door Core Rules. 4. Regels en semantische gronding Regels begrenzen het gedrag op verschillende niveaus. Agent Rules gelden voor de Agent als geheel, terwijl Agent Intent Rules specifieke Agent Intents begrenzen. Core Rules leggen generieke regels vast die samenhangen met de gedragsregimes. Deze regels kunnen Elements gebruiken als semantische context. Daarmee wordt expliciet vastgelegd welke canonieke begrippen en definities nodig zijn om een regel correct te interpreteren en toe te passen. Er ontstaat zo een onderscheid tussen wat wordt bestuurd — Agent en Agent Intent — en waarmee de regels semantisch worden gegrond — Elements. 5. Packaging Een Agent Package brengt de voor inzet benodigde specificatie bijeen. De Knowledge Specification bepaalt de scope van het package en het package behoort tot maximaal één Agent. Het package vormt daarmee de overdraagbare vorm waarin de gespecificeerde Agent beschikbaar kan worden gemaakt. 6. Kern in één zin De Knowledge Specification bepaalt de kenniscontext, de Agent en zijn Agent Intents bepalen de aangeboden dienstverlening, regimes bepalen de gedragsruimte, regels begrenzen die ruimte en Elements leveren waar nodig de canonieke betekenis waarmee die regels worden geïnterpreteerd. Deze zesdelige structuur zou ik ook voor de eerdere Entoli Canon-view gebruiken. Daardoor krijgen de viewbeschrijvingen een herkenbaar architectuurformat, terwijl alleen de relevante secties per view hoeven te worden ingevuld.
