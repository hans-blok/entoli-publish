orchestration specification ()
DEFINITIE Een Orchestration Specification is de herbruikbare specificatie van een samenhangende, geordende reeks Execution Step Specifications die gezamenlijk een doelgericht proces vormen. Zij bestaat onafhankelijk van een Entoli Context en kan door meerdere Entoli Contexts worden gebruikt. DOEL Het expliciet en reproduceerbaar vastleggen van hoe meerdere uitvoeringsstappen worden gecombineerd en geordend tot één samenhangende orchestratie, los van de context waarin die orchestratie wordt gebruikt. LEIDENDE VRAAG Welke uitvoeringsstappen vormen samen de orchestratie en in welke volgorde worden zij uitgevoerd? SAMENSTELLING Een Orchestration Specification bestaat uit één of meerdere Execution Step Specifications. De volgorde van deze stappen maakt onderdeel uit van de orchestratiespecificatie. De wijze waarop deze volgorde technisch wordt vastgelegd behoort niet tot het conceptuele model. RELATIES Een Orchestration Specification kan door nul of meer Entoli Contexts worden gebruikt; een Entoli Context gebruikt nul of meer Orchestration Specifications. Het gebruik wordt aan de zijde van de Entoli Context vastgelegd; de Orchestration Specification zelf verwijst niet naar een Entoli Context. Iedere Orchestration Specification bestaat uit één of meerdere Execution Step Specifications. Iedere Execution Step Specification behoort tot precies één Orchestration Specification. BEPERKINGEN Een Orchestration Specification is geen concrete uitvoering en specificeert niet zelf welke Agent Intent of welk LLM Model voor een individuele stap wordt gebruikt. Die verantwoordelijkheid ligt bij de Execution Step Specification en de daaraan gerelateerde configuratie. INVARIANTEN Iedere Orchestration Specification bevat minimaal één Execution Step Specification en legt een eenduidige ordening van haar Execution Step Specifications vast. Haar bestaan en betekenis zijn onafhankelijk van de Entoli Contexts die haar gebruiken. Voorbeelden: - Van domeinuitspraken naar logisch model — Geordende orchestratie: NIAM-analyse → conceptuele modellering → logisch modelleren → modelreview. - Herzien Agent Development Canon — Geordende reeks stappen voor inventariseren → semantisch reviewen → besluiten → herschrijven → conformance review. - Review conceptueel datamodel — Orchestratie voor modelinspectie → inconsistentieanalyse → besluitvorming → reviewartifact.
