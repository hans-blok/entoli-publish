View documentation — Canon Structure Name: Canon Structure Purpose This view describes the structural composition of a Canon and the relationship between its semantic model and normative rules. It shows how a knowledge specification is realized as a Canon and how the Canon makes domain knowledge explicit through semantic elements, relationships, and rules. Scope The view covers the conceptual structure of a Canon. It does not describe the physical representation, storage technology, file structure, or execution of the Canon. Viewpoint Conceptual / semantic structure. Description A Knowledge Specification specifies a Knowledge Domain and is realized by a Canon. A Canon is composed of two complementary parts: a Semantic Model, which makes the relevant domain semantics explicit; Rules, which express normative constraints governing those semantics. The Semantic Model is composed of Elements and Relationships. Elements represent the concepts or other semantic objects recognised by the model. Relationships connect those elements and make their semantic structure explicit. A Relationship is directed. It has: a source — the Element from which the relationship originates; a target — the Element to which the relationship points. The source and target describe the structural anatomy of a relationship. They are distinct from the relationship type, which expresses the semantic meaning of that relationship, such as is-composed-of, specifies, realizes, or constrains. Rules constrain elements of the Semantic Model. Together, the Semantic Model and Rules form the Canon: the Semantic Model establishes what is recognised and how it is related; the Rules establish what is normatively required, permitted, or prohibited. Canon realizes Knowledge Specification Makes the knowledge specification explicit and authoritative. Canon is composed of Semantic Model The Semantic Model is a constituting part of the Canon. Canon is composed of Rule Rules are constituting parts of the Canon. Semantic Model is composed of Element Elements constitute the semantic content of the model. Semantic Model is composed of Relationship Relationships constitute the semantic structure of the model. Relationship has source Element Identifies the originating Element of a directed relationship. Relationship has target Element Identifies the receiving Element of a directed relationship. Rule constrains Element Expresses a normative constraint concerning an Element. Modelling principle The view deliberately separates semantic meaning from technical representation. source and target are properties of the abstract Relationship concept; they do not imply a particular graph technology. A graph database may implement these as from and to, but that implementation is outside the scope of this view. Interpretation The view should be read according to the following conceptual chain: Knowledge Domain ← Knowledge Specification ← Canon → { Semantic Model + Rules } Within the Semantic Model: Element ← source — Relationship — target → Element The essential proposition expressed by the view is: A Canon realizes a knowledge specification through an explicit semantic model and normative rules. The semantic model establishes the elements and their relationships; the rules constrain the semantics expressed by that model.
