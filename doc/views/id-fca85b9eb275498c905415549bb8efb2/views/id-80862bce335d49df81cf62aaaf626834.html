DEFINITIE Agent Development is het ontwikkelen van kennis, modellen, specificaties, software en andere professionele werkproducten met inzet van Agents als uitvoerende professionele functies. Het begrip beschrijft daarmee een manier van ontwikkelen mét Agents, niet uitsluitend het ontwikkelen ván Agents. Het ontwikkelen en onderhouden van Agents kan zelf onderdeel zijn van Agent Development, maar is slechts één mogelijke toepassing. DOEL Deze view toont het conceptuele objectmodel dat nodig is om ontwikkelwerk met Agents expliciet te specificeren, te organiseren, uit te voeren en te beheersen. De view maakt zichtbaar hoe kennis en canon, professionele functies en intents, regels en execution regimes, orchestratie, modelkeuze, instructies, menselijke context en werkproducten samenkomen in concrete Executions. LEIDENDE VRAAG Welke concepten en samenhangen zijn nodig om ontwikkelwerk met Agents op een expliciete, herhaalbare en beheerste manier te organiseren en uit te voeren? SCOPE Agent Development omvat ontwikkelwerk waarbij Agents professionele werkzaamheden uitvoeren of ondersteunen. Dat kan bijvoorbeeld gaan om domeinanalyse door een NIAM-analist, conceptuele modellering, logisch modelleren, architectuurreview, specificatie, realisatie en testing. Het ontwikkelen of wijzigen van Agents, Agent Intents, Agent Packages en hun canon is eveneens een mogelijke vorm van Agent Development, maar vormt niet de definitie van het begrip. LEESWIJZE De view kan globaal van links naar rechts en van boven naar beneden worden gelezen. Links ligt de semantische grondslag: Knowledge Domain, Knowledge Specification, Canon, Semantic Model, Element en Relationship. Centraal staan de professionele functie en haar contract: Agent, Agent Intent, Rules, Reasoning Mode en Execution Regime. Rechts ligt de operationele configuratie: Operational Context, Orchestration Specification, Execution Step Specification, LLM Model en Model Assignment. Onderaan wordt zichtbaar hoe deze onderdelen voor concrete uitvoering samenkomen in Instruction Set, Execution, Human Context, Handoff en Artifact. KERNSTRUCTUUR Een Knowledge Specification specificeert kennis voor een Knowledge Domain, kan door een Canon worden gerealiseerd en scopet Agent Packages. Een Canon definieert een Semantic Model en canonieke Rules. Een Agent Package bevat Agents; een Agent exposeert Agent Intents. Reasoning Mode en Rules begrenzen het gedrag van Agent en Agent Intent. Voor cognitieve uitvoering worden Source Regime, Synthesis Regime en Task Regime gebruikt als onderscheiden dimensies van Execution Regime. Een Entoli Context gebruikt herbruikbare Orchestration Specifications, die uit Execution Step Specifications bestaan. Een Execution Step Specification roept een Agent Intent aan en kan met een Model Assignment worden geconfigureerd. Voor een concrete Execution wordt een Instruction Set samengesteld uit de relevante semantiek, regels en context. De Execution kan Artifacts en een Handoff produceren. ARCHITECTUURBETEKENIS De view maakt een fundamentele scheiding zichtbaar tussen betekenis, professionele capability, configuratie en runtime. Een Agent is niet de Execution; een Agent Intent is niet de Execution Step Specification; een Semantic Model is niet het Instruction Set; een Orchestration Specification is niet een runtimeproces; en een Artifact is niet hetzelfde als een Handoff. Juist deze scheidingen maken het mogelijk om dezelfde canon, professionele functies en configuraties gecontroleerd in meerdere uitvoeringen en klantcontexten toe te passen. GRENZEN Deze view beschrijft het conceptuele objectmodel en niet de technische implementatie ervan. Zij specificeert geen databaseschema, API-contract, bestandsformaat, deploymentmodel, runtime-infrastructuur of gebruikersinterface. De getoonde Business Objects zijn conceptuele typen; de view toont geen concrete instances. Ook procesvolgorde, lifecycle en technische dataflows worden alleen weergegeven voor zover zij noodzakelijk zijn om de conceptuele relaties te begrijpen. DETAILNIVEAU De view is bedoeld als integrale overzichtsview. Voor precieze definities, invarianten, toegestane waarden en lokale relaties is de documentatie van de afzonderlijke Business Objects leidend. Gespecialiseerde views mogen subsets van dit model tonen om specifieke architectuurvragen te beantwoorden, maar mogen de betekenis van de Business Objects en relaties niet zelfstandig veranderen. VOORBEELD Een NIAM-analist kan als Agent een Agent Intent Analyseer domeinuitspraken exposen. Een Orchestration Specification kan een Execution Step Specification bevatten die dit intent aanroept. Voor een concrete Execution wordt een Instruction Set samengesteld met toepasselijke canonieke semantiek, Rules, Human Context en eventuele bestaande Artifacts of Handoffs. De uitvoering kan vervolgens een conceptueel model als Artifact en relevante interpretatie voor een Logisch modelleur als Handoff produceren.
